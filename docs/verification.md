## v0.1.0 검증 기록

## 수정한 문제

- 이전 실행에서 창을 찾지 못한 문제를 시작 로그와 실제 화면으로 재확인했다. 캐릭터의 `ContentRendered`와 화면 내 좌표가 기록되었으므로, 렌더링 실패가 확인된 것은 아니다. `ShowInTaskbar=False`였던 창을 작업 표시줄에 표시하도록 바꾸고 아이콘을 넣었다. 이후 자동화 도구에서 창을 찾고 실제 캐릭터를 확인할 수 있었으며, 사용자가 작업 표시줄에서도 창을 찾을 수 있게 됐다.
- 실제 패널에서 세 번째 스킨이 다음 줄로 밀리고 하단이 잘리는 현상을 수정했다. 3열 배치와 패널 높이를 조정해 스킨 3종과 종료 버튼이 모두 보이도록 했다.
- 캐릭터 창의 Alt+F4가 앱 전체 종료로 연결되도록 했다. 종료 뒤 Moru 프로세스가 남지 않는 것을 확인했다.
- 패널을 열 때 중복으로 CPU 기준점을 초기화하지 않도록 수정하고, 수치 자체가 접근성 도구에 읽히도록 했다.
- `--diagnostics`로 시작·표시·선택·측정 시작/정지 이벤트를 확인할 수 있다. 일반 실행에는 파일을 기록하지 않는다.

| 패널을 다시 닫음 | 30.53초 | 62.5 ms | 0.0085% | 178.77 MiB | 180.65 MiB | 111.00 MiB |
| 캐릭터까지 모두 숨김 | 30.51초 | 0 ms | 0.0000% | 227.30 MiB | 232.88 MiB | 116.01 MiB |

1. CPU = 프로세스 CPU 시간 증가 ÷ 실제 경과 시간 ÷ 논리 프로세서 수 × 100. 한 코어를 계속 쓰면 이 PC에서는 약 4.17%이다. 앱 화면에 표시되는 **PC 전체 CPU 값**과 다르다.
2. 작업 집합은 해당 프로세스에 현재 상주하는 물리 메모리로 공유 페이지도 포함한다. 작업 관리자의 기본 메모리 열과 정의가 다를 수 있다. MiB = 1,048,576바이트.
3. 전용 커밋은 프로세스 전용으로 커밋된 가상 메모리다. 전부 실제 RAM에 상주한다는 의미는 아니며 작업 집합에 더하면 안 된다.

CPU 부담은 낮았고, 패널을 닫은 뒤 CPU 활동이 감소했다. 숨김 상태의 0은 이 30초 구간에서 카운터 증가가 없었다는 뜻이며 항상 0%임을 보장하지 않는다.
**창을 숨기는 것은 메모리 해제가 아니다.** 패널과 WPF 자원은 재사용하기 위해 남는다. 마지막 숨김 측정에서 메모리가 증가한 결과도 그대로 기록했다. 그 사이 컨텍스트 메뉴와 접근성 검사가 추가됐으므로 숨김 자체가 증가의 원인이라고 단정할 수 없다.
강제 GC, 작업 집합 비우기, 프로세스 우선순위 조절은 사용하지 않았다.

### 화면 검사 없는 별도 실행

UI 검사의 영향을 구분하기 위해 앱을 새로 시작한 뒤 10초 기다리고, 해당 실행에서는 UI 캡처·접근성 조회·입력 없이 같은 방법으로 재측정했다.
패널 실행은 `--show-panel` 옵션을 사용했다. 각각 별도 프로세스이며 장기 대기의 최저 사용량을 측정한 것은 아니다.

재측정에서도 기본 메모리는 비슷했다. 패널의 CPU 평균은 실행마다 달랐으므로 0.137% 하나만 성능 보장치로 안내하지 않는다.

## 재측정

```powershell
# 앱을 실행하고 모루 PID를 확인한 뒤, 측정 중에는 클릭·화면 검사를 하지 않는다.

.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label character-only
# 캐릭터를 클릭해 패널을 열고 실행
```

`measure.ps1`은 프로세스 CPU 누적 시간과 1초 간격 작업 집합·전용 커밋을 읽는다. 표의 최대 메모리는 1초 간격 표본의 최댓값이다.
원시 결과는 로컬 `artifacts/measurement-*.json`에, 개인 컴퓨터의 절대 경로를 제외한 공유용 수치는 [measurements.json](measurements.json)에 보관했다.

## 남은 검증 범위

- 한 PC의 짧은 측정이다. 장시간 메모리 누수, 저사양 PC, 고해상도·다중 모니터에서의 성능은 별도 검증이 필요하다.
- 다중 모니터·DPI 변경·절전 복귀·화면 잠금은 구현되어 있지만 이번에 실제 조건을 바꿔 시험하지 않았다.

- 트레이에서 숨긴 창을 다시 여는 동작은 이번에 직접 조작 검증하지 않았다.
