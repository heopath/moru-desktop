# 첫 버전 검증 기록

기준: 2026-10-18, Windows x64 / .NET SDK 10.0.402 / Release 자체 포함 배포본.

## v0.2.0 추가 검증

- 최종 Release 빌드 성공, 경고 0개·오류 0개.
- 핵심 검사 34개 통과. 기존 22개에 PNG 가져오기, 투명도 보존, 원본 불변, 파일 잠금 해제, 저장 후 복원, 이미지 크기 제한, 외부 URL·상위 경로 거부, 누락 파일 복구 등을 추가했다.
- 앱 실행 옵션으로 PNG 가져오기 → 개인 데이터 폴더에 저장 → 실제 화면 내보내기 → 종료 → 가져오기 옵션 없이 재실행 → 동일 스킨 복원까지 확인했다.
- 기본 새싹·로봇 스킨의 실제 패널·캐릭터를 `docs/images/`에 내보내고 이미지 내용을 확인했다. 사진은 모형이 아니라 실행 중인 WPF 화면을 캡처해 배치한 결과다.
- 사용자 이미지가 네 번째 친구로 추가될 때 패널 높이를 조정하고 긴 이름표를 말줄임 처리했다.
- 새 PNG 추가·화면 저장 버튼의 **파일 선택 대화상자를 통한 직접 조작 검증은 미완료**다. Windows UI 자동화가 `failed to activate captured window`를 반환하여 입력을 중단했다. 실행 옵션은 버튼과 같은 `ImportSkin`·`ExportPreview` 경로를 사용하며, 이 경로와 출력 결과를 검증했다.
- 기본 스킨 클릭·전환은 아래 v0.1.0에서 직접 조작 검증했다. 이번 버전 전체 GUI 검증이 끝났다는 의미는 아니다.

최종 v0.2.0에서 사용자 PNG 복원·소개 화면 내보내기를 마친 후, 패널 2초 갱신 상태로 33.29초 측정했다.
논리 CPU 24개 기준 평균 CPU **0.1643%**(누적 CPU 1,312.5ms), 평균 작업 집합 **197.72 MiB**, 표본 최대 **199.46 MiB**, 평균 전용 커밋 **130.27 MiB**였다.
측정 중 화면 캡처나 입력은 하지 않았다. [v0.2.0 측정 원시 수치와 DLL 해시](measurements-v0.2.json)
한 번의 짧은 관측값이며, 아래 v0.1.0과 통제된 A/B 비교 실험을 한 것은 아니다. 메모리는 공유 페이지를 포함하고 전용 커밋과 합산하지 않는다.

## v0.1.0 검증 기록

## 수정한 문제

- 이전 실행에서 창을 찾지 못한 문제를 시작 로그와 실제 화면으로 재확인했다. 캐릭터의 `ContentRendered`와 화면 내 좌표가 기록되었으므로, 렌더링 실패가 확인된 것은 아니다. `ShowInTaskbar=False`였던 창을 작업 표시줄에 표시하도록 바꾸고 아이콘을 넣었다. 이후 자동화 도구에서 창을 찾고 실제 캐릭터를 확인할 수 있었으며, 사용자가 작업 표시줄에서도 창을 찾을 수 있게 됐다.
- 실제 패널에서 세 번째 스킨이 다음 줄로 밀리고 하단이 잘리는 현상을 수정했다. 3열 배치와 패널 높이를 조정해 스킨 3종과 종료 버튼이 모두 보이도록 했다.
- 캐릭터 창의 Alt+F4가 앱 전체 종료로 연결되도록 했다. 종료 뒤 Moru 프로세스가 남지 않는 것을 확인했다.
- 패널을 열 때 중복으로 CPU 기준점을 초기화하지 않도록 수정하고, 수치 자체가 접근성 도구에 읽히도록 했다.
- `--diagnostics`로 시작·표시·선택·측정 시작/정지 이벤트를 확인할 수 있다. 일반 실행에는 파일을 기록하지 않는다.

## 실제 자원 사용량

환경: AMD Ryzen AI 9 HX 370, 논리 프로세서 24개, 사용 가능한 전체 물리 RAM 약 27.6 GiB, Windows 빌드 26300.9711.
다른 프로그램이 실행 중인 사용자 PC에서 측정했다. 진단 로그는 끈 일반 실행이다.

아래는 같은 프로세스(PID 7224)를 차례로 조작한 뒤 각 상태에서 약 30초 동안 측정한 값이다. 측정 구간에는 UI 캡처·입력을 하지 않았다. 앞선 UI 검사로 로드된 접근성 구성요소나 캐시가 메모리에 남아 있을 수 있다.

| 상태 | 시간 | CPU 시간 증가 | 평균 CPU¹ | 평균 작업 집합² | 최대 작업 집합 | 평균 전용 커밋³ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 시작 후 캐릭터만 표시 | 30.60초 | 562.5 ms | 0.0766% | 165.19 MiB | 165.50 MiB | 98.89 MiB |
| 패널 표시, 2초 갱신 | 30.53초 | 1,000 ms | 0.1365% | 184.41 MiB | 187.29 MiB | 114.43 MiB |
| 패널을 다시 닫음 | 30.53초 | 62.5 ms | 0.0085% | 178.77 MiB | 180.65 MiB | 111.00 MiB |
| 캐릭터까지 모두 숨김 | 30.51초 | 0 ms | 0.0000% | 227.30 MiB | 232.88 MiB | 116.01 MiB |

1. CPU = 프로세스 CPU 시간 증가 ÷ 실제 경과 시간 ÷ 논리 프로세서 수 × 100. 한 코어를 계속 쓰면 이 PC에서는 약 4.17%이다. 앱 화면에 표시되는 **PC 전체 CPU 값**과 다르다.
2. 작업 집합은 해당 프로세스에 현재 상주하는 물리 메모리로 공유 페이지도 포함한다. 작업 관리자의 기본 메모리 열과 정의가 다를 수 있다. MiB = 1,048,576바이트.
3. 전용 커밋은 프로세스 전용으로 커밋된 가상 메모리다. 전부 실제 RAM에 상주한다는 의미는 아니며 작업 집합에 더하면 안 된다.

CPU 부담은 낮았고, 패널을 닫은 뒤 CPU 활동이 감소했다. 숨김 상태의 0은 이 30초 구간에서 카운터 증가가 없었다는 뜻이며 항상 0%임을 보장하지 않는다.
**창을 숨기는 것은 메모리 해제가 아니다.** 패널과 WPF 자원은 재사용하기 위해 남는다. 마지막 숨김 측정에서 메모리가 증가한 결과도 그대로 기록했다. 그 사이 컨텍스트 메뉴와 접근성 검사가 추가됐으므로 숨김 자체가 증가의 원인이라고 단정할 수 없다.
강제 GC, 작업 집합 비우기, 프로세스 우선순위 조절은 사용하지 않았다.

### 화면 검사 없는 별도 실행

UI 검사의 영향을 구분하기 위해 앱을 새로 시작한 뒤 10초 기다리고, 해당 실행에서는 UI 캡처·접근성 조회·입력 없이 같은 방법으로 재측정했다.
패널 실행은 `--show-panel` 옵션을 사용했다. 각각 별도 프로세스이며 장기 대기의 최저 사용량을 측정한 것은 아니다.

| 상태 | PID | 시간 | CPU 시간 증가 | 평균 CPU | 평균 작업 집합 | 최대 작업 집합 | 평균 전용 커밋 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 캐릭터만 표시 | 40080 | 30.59초 | 875 ms | 0.1192% | 167.62 MiB | 168.65 MiB | 100.42 MiB |
| 패널 표시, 2초 갱신 | 38352 | 31.05초 | 2,656.25 ms | 0.3565% | 182.76 MiB | 187.97 MiB | 113.08 MiB |

재측정에서도 기본 메모리는 비슷했다. 패널의 CPU 평균은 실행마다 달랐으므로 0.137% 하나만 성능 보장치로 안내하지 않는다.
두 실행에서 관측된 평균 범위는 캐릭터 CPU 0.077~0.119% / 작업 집합 165~168 MiB, 패널 CPU 0.137~0.357% / 작업 집합 183~184 MiB다. 이 범위는 두 관측값을 요약한 것으로 통계적 상한이나 모든 환경의 예상 범위가 아니다.

## 재측정

```powershell
# 앱을 실행하고 모루 PID를 확인한 뒤, 측정 중에는 클릭·화면 검사를 하지 않는다.
Get-Process Moru | Select-Object Id, Path
.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label character-only
# 캐릭터를 클릭해 패널을 열고 실행
.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label panel-open-2s
# 패널을 닫고 실행
.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label panel-closed
```

`measure.ps1`은 프로세스 CPU 누적 시간과 1초 간격 작업 집합·전용 커밋을 읽는다. 표의 최대 메모리는 1초 간격 표본의 최댓값이다.
원시 결과는 로컬 `artifacts/measurement-*.json`에, 개인 컴퓨터의 절대 경로를 제외한 공유용 수치는 [measurements.json](measurements.json)에 보관했다.
측정한 앱 DLL의 SHA-256: `8DD77EB55A25D34138AAF297A2ABDBD8DC2D637C90BD49E47ABECBD90575BDB6`.

## 남은 검증 범위

- 한 PC의 짧은 측정이다. 장시간 메모리 누수, 저사양 PC, 고해상도·다중 모니터에서의 성능은 별도 검증이 필요하다.
- 다중 모니터·DPI 변경·절전 복귀·화면 잠금은 구현되어 있지만 이번에 실제 조건을 바꿔 시험하지 않았다.
- 드래그 입력과 위치 저장 코드는 실행되었으나, 자동화 드래그로 좌표가 실제로 달라지는 것은 확인하지 못했다. 드래그 이동과 이동 후 위치 복원은 검증 완료 항목에 포함하지 않는다.
- 트레이에서 숨긴 창을 다시 여는 동작은 이번에 직접 조작 검증하지 않았다.
- Codex 사용량·작업 연동과 다른 프로그램 투명도 기능은 아직 포함되지 않았다. PNG 등록은 v0.2.0에서 추가했다.
