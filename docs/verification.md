# 모루 검증 기록

기준: 2026-10-18, Windows x64 / .NET SDK 10.0.402 / Release 자체 포함 배포본.

## v0.10.0 캐릭터 백업·복원

- Release 빌드 경고·오류 0, 핵심 검사 178개 통과. 이름·선택·기본/다섯 상태 PNG의 왕복, 기존 친구 보존, 반복 복원 중복 방지, 변경된 친구의 별도 복사와 재복원, 용량 부족·설정 저장 실패의 부분 적용 방지를 확인했다.
- ZIP 경로 이동·중복 항목·누락 이미지·잘못된 선택·지원하지 않는 버전·해시 불일치·크기 초과·손상 PNG를 거부한다. 실패한 내보내기는 이전 정상 백업을 덮어쓰지 않으며, 캐릭터 저장 폴더로 백업하는 것도 거부한다.
- 일반 Windows 탐색기에서 설치 도우미를 실행해 0.9.0 → 0.10.0으로 업데이트했다. 설치 종료 코드 0, 실제 사용자 설정·캐릭터 JSON·PNG 19개 파일 SHA-256 동일, 자동 실행 꺼짐을 확인했다. 바탕화면 `모루 실행`을 더블클릭해 새 설정과 우사기 선택을 확인했다.
- 실제 설치 앱의 **백업 저장** 버튼과 Windows 저장 창으로 사용자 캐릭터 4명·PNG 14장을 백업했다. 선택한 우사기의 변경한 이름과 다섯 상태가 포함됐으며, 압축 안의 PNG 14장 모두 업데이트 전 원본과 SHA-256이 같았다. 개인 백업과 테스트 원본은 공개 저장소·설치 패키지에 포함하지 않았다.
- 사용자 데이터와 분리한 **빈 테스트 프로필**에서 **백업 복원** 버튼으로 같은 파일을 불러왔다. 확인 창의 4명·14장, 복원 결과 4명 추가를 확인했다. 다시 복원한 결과는 0명 추가·기존 4명으로 중복이 없었다.
- 테스트 앱을 정상 종료·재실행한 뒤 우사기 선택·이름과 쉬는 중/작업 중/완료/확인 대기/오류 전용 이미지 다섯 개를 설정 화면에서 각각 확인했다. 저장된 14장도 모두 원본과 동일했고 AI 연결 꺼짐은 유지됐다. 실제 사용자 캐릭터를 삭제해서 시험하지 않았으며 다른 PC·Windows 계정으로의 이전이나 실제 재부팅은 시험하지 않았다.
- 백업 읽기·내보내기는 요청 때만 실행한다. 새 타이머·네트워크 전송·상시 감시를 추가하지 않았다. 이 버전의 CPU·메모리는 별도로 재측정하지 않았다.

## v0.8.1 재실행·업데이트·재설치 보존

이전 설치 도구 검사는 도구 실행 환경 기준이었다. 이후 일반 Windows 탐색기로 실행하면 같은 AppData 경로의 데이터가 다르게 보이는 현상을 재현했고, 일반 실행 쪽에 스킨을 복원했다. 아래 파일 비교 기록을 일반 바탕화면 실행 검증과 동일하게 해석하지 않는다.

- 정상 종료 후 바탕화면의 `모루 실행.lnk`로 재실행했다. 설치된 EXE와 `--show-panel` 인수를 확인했고, 이름을 바꾼 우사기 선택, 사용자 캐릭터 4개와 기본 캐릭터 3개, 다크 모드·글자 18 설정이 유지됐다.
- 설치 도우미의 설정 읽기·재저장을 제거했다. 읽기 오류가 기본값 저장으로 이어질 수 있는 경로를 없애고 설치·제거가 사용자 데이터 파일을 수정하지 않도록 했다.
- 실제 사용 중인 0.8.0 설치 위치에 0.8.1을 덮어 설치한 뒤, 같은 설치본을 제거하고 재설치했다. 세 단계 모두 종료 코드 0. 단계마다 설정·캐릭터 JSON·PNG 총 19개 파일의 SHA-256이 동일했다. 진단 로그는 비교에서 제외했다.
- 재설치 후 바탕화면 바로가기 대상·인수가 올바르며 자동 실행 Run 항목은 없음을 확인했다. 원본 PNG나 사용자 캐릭터를 다시 가져오지 않았다.
- Release 빌드와 핵심 검사 138개 통과. 설치 도우미만 변경했으며 상시 측정·애니메이션 작업은 추가하지 않았다. 실제 재부팅이나 다른 Windows 계정으로의 이전은 시험하지 않았다.

## v0.8.0 캐릭터 관리와 설치 파일

- Release 빌드와 핵심 검사 138개 통과. 이름 저장·복원, 같은 이미지 캐시 유지, 기본 캐릭터 숨김·복원, 잘못된 이름, 손상된 설정에서 캐릭터가 모두 사라지는 상황 방지, 삭제 실패 시 원본 정보 보존, 다른 캐릭터가 참조하는 이미지 보존, 설치본별 Claude 연결 정리를 확인했다.
- 별도 테스트 프로필의 실제 설정 화면에서 사용자 PNG 이름을 바꾸고 삭제 확인 창으로 삭제했다. 목록에서 사라지고 앱의 복사본만 제거됐으며 원본 PNG는 유지됐다. 기본 모루를 목록에서 제거한 뒤 기본 캐릭터 복원으로 다시 표시했다. 실제 사용자의 캐릭터는 삭제하지 않았다.
- Inno Setup 6.7.3으로 .NET 포함 x64 설치 EXE를 만들었다. 한국어 경로의 테스트 폴더에 무인 설치한 종료 코드 0, 설치 후 통합 설정 도우미 종료 코드 0을 확인했다. 바탕화면 바로가기의 대상과 `--show-panel` 인수, 현재 사용자 앱 제거 등록을 확인했다.
- 설치된 EXE로 별도 프로필을 실행해 실제 소개 PNG를 내보내고 정상 종료했다. 기존 사용자 설정의 모든 이전 필드와 선택된 우사기 ID가 보존됐고 자동 실행 Run 항목은 없었다.
- 테스트 설치본을 제거한 종료 코드 0, 앱 파일·앱 제거 등록 해제, 사용자 데이터 전체 파일의 SHA-256 보존을 확인했다.
- 이름 변경 후 목록이 다시 만들어지는 시점에 선택 강조가 풀리는 현상을 발견해 템플릿 생성 뒤 선택 표시를 복구하도록 수정했다. 수정 후 핵심 검사는 재통과했으나 사용자가 Esc로 화면 조작을 중지하여 이 보정의 최종 화면 재확인은 완료하지 않았다.
- 한 대의 Windows PC에서 검증했으며 새 PC/가상 머신, 실제 재부팅, 다양한 백신·SmartScreen 평판까지 검증한 것은 아니다. 설치 파일은 현재 코드 서명되지 않았다. v0.8.0의 자원 사용량을 별도로 재측정하지 않았으며 아래 측정치는 각 이전 버전의 기록이다.

## v0.7.0 추가 검증

- Release 빌드 경고·오류 0개, 핵심 검사 119개 통과. 상태 이미지 저장·복원·교체·초기화, 원본 보존, 실패 시 이전 정보 보존, 손상된 선택 이미지의 기본 이미지 대체, 경로 이동 공격 거부, 바로가기 실제 저장·읽기를 검사했다.
- 실제 설정의 자동 실행 스위치를 켜면 현재 사용자 Run 키의 Moru 항목에 인용된 실행 파일 경로와 `--startup`이 등록되고, 끄면 해당 항목이 없어지는 것을 확인했다. 마지막 상태는 꺼짐이다. 실제 PC 재부팅·Windows 로그인 자체는 시험하지 않았다.
- 첫 일반 실행에 바탕화면 바로가기가 현재 배포본을 가리키도록 생성됐다. `--show-panel` 인수, 작업 폴더, exe 아이콘을 확인했다. `--data-dir` 시험 실행에서는 시작 등록 및 바탕화면 생성 버튼이 비활성화되고 생성 플래그도 false를 유지했다.
- 개인 우사기 PNG 5종을 가져온 후 재실행했으며, 선택 스킨·다섯 상태 이미지와 기존 치이카와 스킨이 유지됐다. 설정의 상태 선택을 바꾸면 노트북을 든 작업 중 모습으로 미리보기가 바뀌는 것을 확인했다. PNG 선택 파일 대화상자는 열렸으나, 자동화 도구에서 해당 모달의 파일명 입력을 완료하지 못했다. 이미지 저장·전환 경로는 자동 검사와 CLI 가져오기로 검증했다.
- 다크 모드에서 친구 목록 이름이 어두운 색으로 보이던 문제도 수정했다. 소개 자료에는 실제 설정 캡처와 앱 자체가 내보낸 다섯 상태 GIF를 사용했다.
- 소스 확인 및 손상 이미지 시험 중 InvalidDataException이 기존 예외 필터에서 빠진 것을 발견해 수정했다.

### v0.7.0 자원 측정

| 대시보드 열림 · 2초 갱신 | 30.73초 | 0.1970% | 205.81 MiB | 211.94 MiB | 141.56 MiB |

`scripts/measure.ps1`로 프로세스 CPU 누적 시간의 차이를 전체 논리 프로세서 수로 나누고 작업 집합을 1초 간격으로 읽었다. 상태별 이미지는 이벤트에 따라 교체하고, 미리보기 복원 타이머는 미리보기 요청 후 한 번만 동작한다. AI 연결·다른 캐릭터·디스플레이·GPU 조건의 부하는 달라질 수 있다.

- 이전 실행에서 창을 찾지 못한 문제를 시작 로그와 실제 화면으로 재확인했다. 캐릭터의 `ContentRendered`와 화면 내 좌표가 기록되었으므로, 렌더링 실패가 확인된 것은 아니다. `ShowInTaskbar=False`였던 창을 작업 표시줄에 표시하도록 바꾸고 아이콘을 넣었다. 이후 자동화 도구에서 창을 찾고 실제 캐릭터를 확인할 수 있었으며, 사용자가 작업 표시줄에서도 창을 찾을 수 있게 됐다.
- 실제 패널에서 세 번째 스킨이 다음 줄로 밀리고 하단이 잘리는 현상을 수정했다. 3열 배치와 패널 높이를 조정해 스킨 3종과 종료 버튼이 모두 보이도록 했다.
- 캐릭터 창의 Alt+F4가 앱 전체 종료로 연결되도록 했다. 종료 뒤 Moru 프로세스가 남지 않는 것을 확인했다.
- 패널을 열 때 중복으로 CPU 기준점을 초기화하지 않도록 수정하고, 수치 자체가 접근성 도구에 읽히도록 했다.
- `--diagnostics`로 시작·표시·선택·측정 시작/정지 이벤트를 확인할 수 있다. 일반 실행에는 파일을 기록하지 않는다.

## 실제 자원 사용량

환경: AMD Ryzen AI 9 HX 370, 논리 프로세서 24개, 사용 가능한 전체 물리 RAM 약 27.6 GiB, Windows 빌드 26300.9711.
다른 프로그램이 실행 중인 사용자 PC에서 측정했다. 진단 로그는 끈 일반 실행이다.

아래는 같은 프로세스(PID 7224)를 차례로 조작한 뒤 각 상태에서 약 30초 동안 측정한 값이다. 측정 구간에는 UI 캡처·입력을 하지 않았다. 앞선 UI 검사로 로드된 접근성 구성요소나 캐시가 메모리에 남아 있을 수 있다.

| 상태 | 시간 | CPU 시간 증가 | 평균 CPU¹ | 평균 작업 집합² | 최대 작업 집합 | 평균 전용 커밋³ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 시작 후 캐릭터만 표시 | 30.60초 | 562.5 ms | 0.0766% | 165.19 MiB | 165.50 MiB | 98.89 MiB |
| 패널 표시, 2초 갱신 | 30.53초 | 1,000 ms | 0.1365% | 184.41 MiB | 187.29 MiB | 114.43 MiB |
| 패널을 다시 닫음 | 30.53초 | 62.5 ms | 0.0085% | 178.77 MiB | 180.65 MiB | 111.00 MiB |
| 캐릭터까지 모두 숨김 | 30.51초 | 0 ms | 0.0000% | 227.30 MiB | 232.88 MiB | 116.01 MiB |

1. CPU = 프로세스 CPU 시간 증가 ÷ 실제 경과 시간 ÷ 논리 프로세서 수 × 100. 한 코어를 계속 쓰면 이 PC에서는 약 4.17%이다. 앱 화면에 표시되는 **PC 전체 CPU 값**과 다르다.
2. 작업 집합은 해당 프로세스에 현재 상주하는 물리 메모리로 공유 페이지도 포함한다. 작업 관리자의 기본 메모리 열과 정의가 다를 수 있다. MiB = 1,048,576바이트.
3. 전용 커밋은 프로세스 전용으로 커밋된 가상 메모리다. 전부 실제 RAM에 상주한다는 의미는 아니며 작업 집합에 더하면 안 된다.

CPU 부담은 낮았고, 패널을 닫은 뒤 CPU 활동이 감소했다. 숨김 상태의 0은 이 30초 구간에서 카운터 증가가 없었다는 뜻이며 항상 0%임을 보장하지 않는다.
**창을 숨기는 것은 메모리 해제가 아니다.** 패널과 WPF 자원은 재사용하기 위해 남는다. 마지막 숨김 측정에서 메모리가 증가한 결과도 그대로 기록했다. 그 사이 컨텍스트 메뉴와 접근성 검사가 추가됐으므로 숨김 자체가 증가의 원인이라고 단정할 수 없다.
강제 GC, 작업 집합 비우기, 프로세스 우선순위 조절은 사용하지 않았다.

### 화면 검사 없는 별도 실행

UI 검사의 영향을 구분하기 위해 앱을 새로 시작한 뒤 10초 기다리고, 해당 실행에서는 UI 캡처·접근성 조회·입력 없이 같은 방법으로 재측정했다.
패널 실행은 `--show-panel` 옵션을 사용했다. 각각 별도 프로세스이며 장기 대기의 최저 사용량을 측정한 것은 아니다.

## 재측정

```powershell
# 앱을 실행하고 모루 PID를 확인한 뒤, 측정 중에는 클릭·화면 검사를 하지 않는다.
Get-Process Moru | Select-Object Id, Path
.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label character-only
# 캐릭터를 클릭해 패널을 열고 실행
.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label panel-open-2s

.\scripts\measure.ps1 -ProcessId <PID> -Seconds 30 -Label panel-closed
```

`measure.ps1`은 프로세스 CPU 누적 시간과 1초 간격 작업 집합·전용 커밋을 읽는다. 표의 최대 메모리는 1초 간격 표본의 최댓값이다.
원시 결과는 로컬 `artifacts/measurement-*.json`에, 개인 컴퓨터의 절대 경로를 제외한 공유용 수치는 [measurements.json](measurements.json)에 보관했다.
